## 1. Core Architectural Decisions (D1 – D21)

| ID | Decision | Choice | Rationale |
|----|----------|--------|-----------|
| **D1** | **Backend Stack** | Python 3.12 + FastAPI (async) | Modern async runtime, native Windows development support without Docker, fast SSE streaming. |
| **D2** | **Vector Store** | **ChromaDB** (embedded persistent mode) + **SQLite FTS5** | In-process execution in Python 3.12 without external Docker daemons; dense embeddings stored in ChromaDB, sparse keywords in SQLite FTS5, combined via Reciprocal Rank Fusion (RRF). Pluggable via `VectorStorePort`. **Default ONNX embedder explicitly disabled** to save ~250 MB RAM. |
| **D3** | **Graph Store** | **KùzuDB** (`kuzu` embedded in-process database) | Replaced heavy Neo4j JVM container. Runs embedded in Python, native Cypher support, < 100 MB RAM footprint, zero Docker container requirements. Pluggable via `GraphStorePort`. |
| **D4** | **Structured Tabular Store** | **SQLite** (read-only mode) + AST SQL Guard | Excel and CSV sheets loaded as typed tables; LLM generates read-only `SELECT` statements validated against an allow-list AST parser. |
| **D5** | **Source of Truth** | **Document Registry** (SQLite) + Outbox | SQLite with WAL mode stores document metadata, SHA-256 hashes, version trees, and outbox queue. Vector, graph, and SQL indexes are derived and rebuildable from original files. |
| **D6** | **Server Access Control** | Static Master Key (`X-API-Key`) | Single-tenant deployment without user registration/login screens. Server protected via static secret header passed by the frontend. |
| **D7** | **LLM Inference & Billing** | **Bring Your Own Key (BYOK)** via OpenRouter | User provides their personal OpenRouter key via `X-OpenRouter-Key` request header. Zero LLM cost/token liability for the server host. Key is validated live, used ephemerally in-memory, and never persisted to database or disk. Stored only in browser client storage. |
| **D8** | **Private Mode** | Config-Driven Toggle (`llm.private_mode: false`) | Architectural switch allowing local Ollama endpoints for testing correctness on local workstations. Disabled for demo on 2-vCPU VPS. |
| **D9** | **Decision Backend** | Prompt-Based Judge (Cloud LLM) — *implementation details superseded by D22* | Julia-1 container dropped to conserve RAM. Abstract `DecisionBackendPort` used for G1–G4 guardrails. See D22 for the implemented backends and the Jev/Julia-1 deferral. |
| **D10** | **Observability Integration** | Reuse Host Prometheus & Grafana | FastAPI exposes `/metrics`. Hooks into pre-existing Prometheus/Grafana already running on the demo machine for another project. Zero duplicate monitoring containers. |
| **D11** | **Ingestion Flow** | Asynchronous with Status Polling | Ingestion runs asynchronously via SQLite outbox. Frontend polls `GET /api/v1/documents/{id}` for stage, percentage, and page counts. |
| **D12** | **Ingestion Idempotency** | Canonical Content-Hash (SHA-256) | Duplicate file upload with identical SHA-256 is an immediate `200 OK` no-op. Re-uploading with identical name but modified content creates an atomic version increment. |
| **D13** | **Output Verification & Rewrites** | Bounded Rewrite Loop (Max 2 attempts) | Model returns chunk IDs. Server resolves to verified physical page/line/row coordinates. Claims failing verification trigger a structured rewrite feedback loop; unresolvable claims degrade gracefully with warning badges. |
| **D14** | **Zero Hardcoding** | Strict Configuration Separation | All capacities (max documents, file sizes, page limits), model names, temperatures, and thresholds are loaded from `config/config.json`. Secrets reside strictly in `.env`. |
| **D15** | **Starter Questions** | Dedicated Metadata Endpoint | `GET /api/v1/examples` serves curated domain questions from `config/example_questions.json` for immediate demo exploration. |
| **D16** | **Synthetic Data Strategy** | On-Demand Generator Script | No synthetic test documents checked into Git. Generated on demand via `python -m app.cli.generate_synthetic_docs`. |
| **D17** | **Engineering Principles** | Hexagonal Ports & Adapters + Layered Design | `api -> service -> repository/adapter` layered architecture. Clear port interfaces, fail-fast mechanics, RFC 7807 problem details, and intelligent retries only. |
| **D18** | **Document Conflict Policy** | Surface Both with Dates/Versions | When solicitations or proposals state conflicting guidelines, the LLM writer highlights both contradictory claims with their respective document dates and versions. |
| **D19** | **Frontend Technology** | **Thin HTML5/CSS3/Vanilla JS SPA** | Modern zero-build single-page application served statically by FastAPI. Streamlit is explicitly rejected (inflexible SSE streaming, high memory, and difficult citation modal integration). |
| **D20** | **Two-Phase Delivery** | Windows Native First → VPS Dockerization | Phase 1 runs natively on Windows 11 with zero Docker dependencies for fast development. Phase 2 packages into a multi-stage Docker container (`docker-compose.yml`) for VPS demo and rubric compliance. |
| **D21** | **PDF Extraction Library** | **`pypdf`** + `openpyxl`/`pdfplumber` | Permissive BSD license for text extraction avoiding AGPL viral licensing issues (such as PyMuPDF). Fast, lightweight, and page-exact. |

## 2. Architectural Conflict Resolutions (C1 – C4)

| Conflict ID | Initial Conflict | Resolution & Engineering Rationale |
|-------------|------------------|------------------------------------|
| **C1** | Full stack memory (> 6 GB) vs 8 GB host with existing services | **Resolved:** Dropped Neo4j JVM (~1.2 GB) for embedded KùzuDB (~100 MB). Replaced external Qdrant container with in-process ChromaDB. Dropped Julia-1 daemon. Reused host's pre-existing Prometheus/Grafana instances. Total GrantLoom memory reduced to **< 2.5 GB RAM**. |
| **C2** | Private mode on 2-vCPU VPS | **Resolved:** Private mode is an optional configuration toggle (`llm.private_mode: false`). Demo runs in cloud BYOK mode. Local Ollama testing supported on developer laptop. |
| **C3** | Public demo VPS vs "No Login" | **Resolved:** Protected by `X-API-Key` server secret header + reverse proxy TLS/rate limiting. No login UI required. |
| **C4** | Neo4j JVM memory footprint | **Resolved:** Dropped Neo4j completely. Adopted **KùzuDB** behind `GraphStorePort`. Kùzu runs embedded in Python 3.12, parses Cypher natively, and requires no background daemon. |

## 3. Detailed Design Decisions (O1 – O18)

| # | Topic | Decision | Details |
|---|-------|----------|---------|
| **O1** | Target Host | 8 GB VPS (< 2.5 GB allocated) | Runs comfortably on the 8 GB host alongside pre-existing Prometheus and Grafana. |
| **O2** | Private Mode | Config-Driven Toggle | `llm.private_mode: false` in `config.json`. Points to local Ollama if enabled for testing. |
| **O3** | Ingestion Injection Scan | Two-Tier Hybrid Pipeline | 100% regex heuristic scan + targeted LLM verification for flagged chunks and 2% random sample. Cached by chunk hash. |
| **O4** | Graph Entity Schema | Minimal Schema (v1) | Node types: `Document`, `Requirement`, `Person`, `Project`, `Funder`. Evaluated via retrieval ablation. |
| **O5** | Cypher Querying | Parameterized Templates Only | Zero free-form Cypher generated in v1 to eliminate Cypher injection and syntax hallucinations. |
| **O6** | Document Identity | SHA-256 Content Hash | Hash is canonical ID. Duplicate hash = no-op. Same name + new hash = version increment. |
| **O7** | Non-English Queries | Strict Polite Refusal | G1 input guard rejects non-English queries immediately without initiating RAG retrieval. |
| **O8** | Embedding Model | Cloud OpenRouter / OpenAI Embeddings | Cloud embeddings by default to avoid local CPU/RAM overhead on 2-vCPU host; local embedding option supported via config. |
| **O9** | Answer Caching | Disabled in v1 | Full-answer caching disabled to avoid stale responses during demo; extraction and embeddings cached by content hash. |
| **O10** | Log Data Privacy | Anonymized Logs Only | `logging.log_full_prompts: false` by default. Only metadata, latencies, and token counts logged. |
| **O11** | Rewrite Retry Limits | Maximum 2 Iterations | Bounded rewrite loop. Degrades gracefully to partial answer with warning badges if claims cannot be resolved. |
| **O12** | Refusal Templates | Versioned Markdown Files | Refusal copy stored in `templates/refusals/*.md`. Loaded dynamically. |
| **O13** | Coordinate Citations | Media-Specific Coordinates | PDF = Page + text snippet; TXT = Line Range; CSV/XLSX = Sheet + Row Number + Column Header. |
| **O14** | Backup and Restore | Deferred as `[TODO]` | Deferred for post-demo. SQLite registry + raw files form 100% rebuildable state. |
| **O15** | Domain & Reverse Proxy | Host Nginx Reverse Proxy | Nginx terminates TLS and enforces IP/rate limiting with SSE buffering disabled. |
| **O16** | Quarantine Retention | 14 Days Retention | Quarantined files retained in quarantine table for 14 days (`guardrails.quarantine_retention_days = 14`). |
| **O17** | Document Conflict Resolution | Highlight Both with Dates | Prompts instruct model to highlight both conflicting terms along with their respective dates/versions. |
| **O18** | Compliance Export Format | JSON + Downloadable Excel | Screen JSON view + downloadable `.xlsx` generated via `openpyxl`. |

## 4. Review-02 Decisions (D22 – D26, 2026-10-13)

| ID | Decision | Choice | Rationale |
|----|----------|--------|-----------|
| **D22** | **Decision Backend (supersedes the backend half of D9)** | `llm_judge` (prompt-based judge, PRD §8.3 `PromptJudgeAdapter`) is the v1 default for G1 semantic screen, G2 routing, G3 context filter, G4 claim verification, Tier-2 ingestion scan and compliance assessment, with a **labelled, metered** `heuristic` fallback (`decision.backend`, `decision.fallback_backend`). **Jev and Julia-1 are deferred**: config rejects `"jev"`/`"julia1"` with a pointer to this entry. | Jev's request/response contract (`jevmodel.org/docs`) could not be verified and no SDK is pinned; Julia-1 has no local runtime in the dependency set. Both remain future implementations of `DecisionBackendPort` (typed methods per gate). Every verdict carries the backend that produced it (SSE `backend` fields, `grantloom_decision_fallbacks_total`), so degradation is visible instead of silent. The data-strategy §3.6 "fallback" mode is what runs when the judge is unreachable. |
| **D23** | **Inference Provider Selection** | The provider is chosen **only** by `llm.private_mode`: `false` → OpenRouter (BYOK header mandatory, probed live); `true` → local Ollama (no key accepted or forwarded). A server-side `OPENROUTER_API_KEY` never changes which client serves requests. | Fixes review-02 §4.1: on a fresh install (no server key) BYOK validation was dispatched to Ollama and any garbage key passed. An `egress` SSE event and `GET /api/v1/info` report provider, destination, role models and decision backend (FR-Q10). |
| **D24** | **Embedding Backend Is Explicit** | `models.embedding_backend: "deterministic" \| "openrouter"`. No silent fallback between them; the vector collection records an embedding fingerprint and refuses to open under a different embedder (`python -m app.cli.reindex` rebuilds). | Prevents mixed embedding spaces (review-01 §4.5). The default stays `deterministic` (lexical hashing, not semantic) so a fresh install needs no server key; this limitation is reported in the egress event and the eval caveats. |
| **D25** | **Access Control Default** | Every `/api/v1` route requires `X-API-Key` when `MASTER_API_KEY` is set; without it, only loopback clients are served, and startup refuses a non-loopback `server.host`. The capability probe accepts no caller-supplied endpoint. | Fixes review-02 §4.2 (unauthenticated reads/exports/admin and an SSRF-capable probe). |
| **D26** | **Evaluation Methodology** | One pipeline for API and eval; isolated temp workspace; golden set rebuilt from facts present in the synthetic corpus; whole-value matching; faithfulness only from an independent judge of a different model family (NFR-6) and never for the offline extractive stub; held-out paraphrased adversarial set reported separately. | Fixes review-02 §3 (circular faithfulness, substring recall, missing held-out set, eval writing into `data/`). Restores the PRD ≥ 0.95 faithfulness target. |
| **D27** | **Public BYOK Demo Mode (Phase 2)** | `server.public_byok: true` (docker deploy config) allows serving non-loopback clients **without** `MASTER_API_KEY`: visitors use the hosted demo with their own `X-OpenRouter-Key`, which every LLM-costing endpoint already requires and live-probes (D23). Document/admin endpoints are open but rate-limited at nginx (30 req/min per IP, burst 15) and by slowapi. Startup refuses `public_byok` combined with `private_mode: true` (free local inference must never be publicly exposed) and logs a loud warning otherwise. | Owner decision for the public demo: zero server-side secrets to manage or leak; cost is inherently capped per visitor because inference only runs on the caller's own key. `/metrics` stays host-only (nginx `deny all`; Prometheus scrapes 127.0.0.1:8092). Trade-off accepted: uploads/deletes are public within `limits.max_documents` (50 × 25 MB) — acceptable for a single-tenant demo appliance, revisit with per-session scoping if the demo goes multi-user. |
| **D28** | **Validate BYOK Once, On Save** | The visitor's OpenRouter key is validated a single time — when the UI saves it (`POST /api/v1/auth/validate-key`) or on the first request carrying it — and the SHA-256 digest is then remembered for the process lifetime (`llm.byok_validation_ttl_seconds: 0`, FIFO-capped by `llm.byok_validated_keys_max`). | Owner directive: per-request validation added a provider round-trip to every question. Security is unchanged because validation was never the enforcement point — every real writer/judge call carries the key and maps upstream 401/402 to RFC 7807 errors, so a revoked or exhausted key fails on the next inference call instead of at a probe. Keys are still never stored or logged, only digests. |
| **D29** | **Streaming Compliance Progress** | `POST /api/v1/compliance/{id}/stream` emits `start` → `progress` (one event per assessed requirement) → `done` (full matrix), and requirement assessment runs with bounded concurrency (`compliance.max_concurrent_assessments`). The JSON endpoint remains and consumes the same generator, so there is one evaluation path. | An audit runs up to `compliance.max_requirements` judge calls; the synchronous endpoint left the UI with no feedback for minutes. Progress events arrive in completion order while records persist in extraction order (`REQ-01..n`), keeping req IDs stable across runs. |
| **D30** | **Corpus Realism: Formula Recovery + Two More Documents** | XLSX extraction re-evaluates the safe arithmetic subset of formulas (`SUM(range)`, `+ - * /` over cell references) when a workbook stores no cached value; unsupported functions stay empty and are never guessed. The synthetic corpus grows from 4 to 6 documents with a cost-share commitment letter and a facilities/capability statement. | Owner directive: the demo needed more documents for realistic results. Generated workbooks store formulas without cached values, so `data_only` readers saw `None` and every total column vanished — the SQL tool then answered budget questions from nothing. Budget totals were also internally inconsistent (Travel rows summed to \$18,150 while the summary claimed \$12,450; Equipment summed to \$151,000 vs a claimed \$68,000 "across three line items" while five items existed; FACT_010 claimed no item exceeded \$50k while the Spectrometer is \$55,000 and marked "Yes"). Fixtures, planted facts and golden expectations Q35/Q36 were aligned to the arithmetic instead of loosening the checks. The two new documents are deliberately free of NSF/NIH content so golden Q44/Q45 remain genuinely unanswerable. |
| **D31** | **No Heuristic, No Fallback Decision Backend (supersedes the fallback half of D22)** | `decision.backend` accepts only `llm_judge` and `jev`; `jev` is the same prompt-based judge implementation pointed at `decision.jev_model` and reported as `jev:<model>` (one code path, review-04 B1). `HeuristicDecisionBackend`, `FallbackDecisionBackend`, `decision.fallback_backend` and `grantloom_decision_fallbacks_total` are deleted; judge retries (bounded by `decision.max_retries`) are metered as `grantloom_decision_retries_total` and a judge that exhausts them raises `DECISION_BACKEND_ERROR` (RFC-7807) — the request fails loudly. The lexical decision double lives in `tests/stub_backend.py` and is injectable only through the eval runner's test-only factory, never through config or CLI. `templates/decision/heuristic_lexicon.json` is reduced to `templates/extraction/extraction_lexicon.json` (entity/requirement cues for pattern-based extraction only). | Owner directive + review-04 A1: a keyword rule engine cannot judge meaning or catch paraphrased injections (held-out block rate 0%), and a fallback chain turned judge outages into silent quality degradation. Extraction cues remain pattern-based deliberately: ingestion must work without credentials (FR-I1); they propose candidate entities/sentences, while every security- and truth-relevant verdict (G1–G4, Tier-2, compliance) comes from the model-based judge. |
| **D32** | **Corpus-Evidence Guard Is Explicit Config; Dev/Docker Configs Must Match** | `decision.corpus_evidence_guard: bool` + `decision.corpus_in_domain_overlap: float` replace the implicit gating on a `heuristic` config block; a unit test asserts `config/config.json` and `deploy/config.docker.json` have identical key sets (only `server.host` / `server.public_byok` values may differ). | Review-04 A2: the G1 corpus-evidence override was silently ON in Docker but OFF in dev because the two configs had drifted. Two environments, two behaviors — now the guard is explicitly ON in both and drift fails the test suite. |
| **D33** | **E2E Suite Removal (record of d353b23→b69f0ce)** | The Playwright E2E suite added in `d353b23` (11 live browser flows + submission PDF) was deleted in `b69f0ce` and `e2e/` gitignored. Rationale (recorded after the fact, review-04 A3): the suite and its artifacts were hackathon-submission evidence, not CI-runnable regression assets — they required a live browser, a deployed stack and real API keys, and could not run in the offline `pytest` gate. | Acknowledged cost: the repo currently has zero browser-level coverage, which is how the duplicate `loadStarterPrompts` defect (review-04 B4) shipped unnoticed. Frontend behavior is covered indirectly by `tests/integration/test_frontend_static.py`; restoring a small headless smoke subset (page load, settings save, ask-stream render) is a known open item. |
| **D34** | **Native Jev Decision Backend via OpenRouter Decisions API** | Implement `JevDecisionBackend` targeting OpenRouter's native `/api/alpha/decisions` endpoint. In accordance with D31, there are zero silent delegate fallbacks. Failed calls or invalid responses retry up to `decision.max_retries` (metered via `grantloom_decision_retries_total`) and fail loudly with `DecisionBackendError` / RFC-7807 `DECISION_BACKEND_ERROR`. Enforces strict parsing of required decision keys (`confidence`, `choice`). | Delivers fast (~300ms) structured guard and routing decisions at ~1/100th the cost of general LLM judge calls, while preserving strict fail-loud system guarantees. |
| **D35** | **Semantic Embeddings as Production Default** | `models.embedding_backend` defaults to `"openrouter"` using `openai/text-embedding-3-small` (1536-dim), superseding the legacy deterministic hash default. Embedding fingerprinting in ChromaDB prevents mixed vector spaces, requiring `python -m app.cli.reindex` on migration. | Ensures high semantic recall across conceptual queries without sacrificing fail-loud index integrity. |
| **D36** | **BM25 Bigram Expansion & Config-Driven Lexical Abstention** | SQLite FTS5 index includes bigram expansions for exact phrase matching on standards and technical codes (e.g. `NFPA 855`, `IEEE 1547`). Retrieval relevance and abstention are governed strictly by configuration (`retrieval.min_bm25_overlap` and `retrieval.min_relevance_threshold`), prohibiting hardcoded token floors. Per-document chunk diversification for composite/hybrid is capped by `retrieval.max_chunks_per_doc`. Known gap: benchmark p95 latency (~47 s) exceeds PRD NFR-1 (single-hop p95 ≤ 15 s); dominated by network retrieval + G3, not yet addressed. | Resolves multi-document technical code retrieval dilution while preserving zero-hardcoding architectural principles. |


| **D37** | **Corpus-Derived Starter Questions** | `/api/v1/examples` now generates starter questions from the actual indexed documents (review-08 F1): keyword, semantic, graph, tabular-SQL and composite templates anchored on real corpus facts, plus a negative control. A template is emitted only when its anchor terms exist in an active chunk (composite questions span documents); an empty corpus falls back to static onboarding prompts. `source_chunks` on each question lets the UI show why it was offered. | Deployed starters previously referenced facts missing from the seeded corpus (e.g. NFPA 855 / IEEE 1547, vendor "Lead Firmware Engineer") and repeatedly failed the pipeline — 3 rewrites then abstention. Generated starters are answerable by construction, so the demo no longer shows zero-result sample questions. |
| **D38** | **Honest Confidence + Verdict Reasons in UI** | G4 per-claim verdict reasons (`confidence_reasons`) stream through the `verify` and `done` events; the aborted/abstention paths report a real reason and stop claiming `confidence_score: 1.0` (review-08 F2). The UI renders a "Verification verdict / Why this result" box with the judge's reasons and downgrades abstained answers from a green 100% to an honest "No answer found in documents". | A 100% confidence badge was shown for abstentions that performed no verification at all. Now the displayed confidence is the actual G4 score, and every rejection explains which claims were unsupported/contradicted and why. |
| **D39** | **Fail-Fast Rewrite Loop on Repeated Verdicts** | The rewrite loop stops early when the *same* rejection verdict repeats (same unsupported claim text / same unresolved citations) instead of burning all `max_rewrite_attempts` (review-08 F3). The rewrite event carries `exhausted_early: true` so the UI can say "gave up after identical rejection" instead of "Rewriting (attempt n)" forever. | Sample questions that the writer could not ground no longer consume 3 slow rewrites before reporting no-answer; the run stops as soon as the outcome is provably identical. |
| **D40** | **Regex-First Prefilters Retained at G1 and Ingestion Tier 1 (review-08)** | The G1 regex prefilter (non-English Unicode scripts, canonical injection phrases) and the ingestion Tier 1 regex scan stay as the first, deterministic layer; the decision backend (Jev / `llm_judge`) remains the semantic layer behind them (G1 `screen_query`; Tier 2 on flagged chunks plus the `tier2_sample_rate` sample). Regex verdicts are labelled `backend: "regex"`. They are a cheap filter, not a complete defence: paraphrased and non-listed-language injections are only caught by the semantic layer (G1) or by the 2% sample (ingestion). | Sending every query and every chunk to Jev adds a model call per chunk with a small context window, which breaks the p95 <= 4.0 s TTFT budget and ingestion throughput. Known residual risks: Latin-script non-English text passes the language gate; an unflagged paraphrased document injection reaches retrieval unless sampled. Mitigations that do not depend on the prefilter: G3 context filter, G4 claim verification against cited chunks, citation-only output (LLM emits `[chunk_id]` markers, no tool/egress authority). |
| **D41** | **Language ID Outside the Model + Untrusted-Text Fencing (review-08)** | (1) G1 and the ingestion scan use an offline language detector (`lingua-language-detector`, port `LanguageDetectorPort`, adapter `LinguaLanguageDetector`) restricted to `guardrails.language_candidates`. G1: after the script and injection regexes and before any model call, a confidently non-English query (`>= language_min_confidence`, `>= language_min_query_words` alphabetic words) is refused with `backend: "lingua"`. Ingestion: confidently non-English chunks (`>= language_min_chunk_words`) are invisible to the English Tier 1 patterns, so they are always sent to Tier 2 and listed in `ScanReport.non_english_chunk_ids`. (2) Third-party text (chunks, filenames, tool evidence, queries, claims) is passed through `neutralize()` so it cannot close a fence; the writer prompt wraps all context in `<<<UNTRUSTED_CONTEXT_<random id> BEGIN/END>>>` and the writer system prompt declares fenced text to be data and requires English output; judge prompts keep `<untrusted>` blocks with the same neutralisation. | A prompt line such as "process only English" is not a control (instruction and attack share one channel). Detection and fencing do not depend on the model obeying. Limits: detection is unreliable on short or acronym/number-heavy text (below the word thresholds it returns "unknown", never "English"); fencing lowers but does not remove injection risk, which is why G3/G4 and the no-tools writer remain. Cost: the wheel is ~160 MB (Docker image size) and detection is ~1-25 ms per text. |
